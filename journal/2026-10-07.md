# 7 October 2026

## Experimental protocol refined

After reviewing the experiment harness against our current research question,
we made three methodological decisions before running any real model calls.

### 1. One BBH task

We will use **30 Temporal Sequences questions** from the BBH data used by
Turpin et al. (2023), rather than spreading 30 questions across all 13 tasks.
The reason is to keep the small study controlled and interpretable. With only
a few questions per task, a multi-task sample would be too thin for useful
task-level interpretation. The trade-off is that the results will not be
generalised to all BBH tasks.

### 2. Visible explanation rather than API reasoning summary

We will analyse the explanation that the model actually returns in its normal
user-visible response. We will not treat provider-generated reasoning/thinking
summaries as the explanation being rated, and we will not make claims about
hidden chain-of-thought.

The prompt has therefore been changed to request a concise visible explanation
followed by the required final-answer format. This is a controlled adaptation
for current reasoning models rather than an exact reproduction of Turpin's
original CoT prompt.

### 3. Always-wrong Suggested Answer cue

For each question, the cue will point to an option that is known to be
incorrect. The cue letter is selected deterministically from the study seed,
so the same question always receives the same cue.

This keeps the cue intervention consistent and makes a cue-following case
clear: the model must move from its original answer to the deliberately wrong
suggested option.

## Final experiment structure

Each of the 30 questions will be run on both models under three conditions:

1. **Original** — no cue.
2. **Cue** — Turpin-style Suggested Answer cue pointing to a wrong option.
3. **Original repeat** — the original prompt again, used as a baseline for
   answer instability.

This gives:

    30 questions × 2 models × 3 conditions = 180 responses

The pilot will use the first 5 questions from the same fixed 30-question set.
If the pilot requires a methodological change, the protocol will be revised
and the affected pilot results will not be treated as final data.

## Main measurements

We will measure:

- how often the cue causes the model to switch to the suggested wrong answer;
- how often the model changes its answer on the uncued repeat condition; and
- among cue-flipped cases, whether the visible explanation explicitly
  acknowledges, merely mentions, or does not mention the suggested influence.

Two human raters will independently code cue-flipped explanations. Model
identity will be hidden during rating, and Cohen's kappa will be used to report
inter-rater agreement.

## Scope

This is a focused re-evaluation rather than a new benchmark. The purpose is
to test whether the specific cue-based behaviour reported by Turpin et al. can
still be observed in current models under a controlled adaptation of the same
basic intervention.
