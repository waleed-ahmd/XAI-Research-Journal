### What happened

Reviewed both open harness PRs with Claude Code's `/code-review`: [#10](https://github.com/waleed-ahmd/XAI-Research-Journal/pull/10) (flagship-model switch + `.env` loading fix) and [#11](https://github.com/waleed-ahmd/XAI-Research-Journal/pull/11) (two completed experiments' results plus small code fixes). Merged #10 first, then resolved the merge conflicts that created on #11 and pushed the fix. Opened [#12](https://github.com/waleed-ahmd/XAI-Research-Journal/issues/12), a tracking issue for lower-priority code-quality findings from the review, and [#13](https://github.com/waleed-ahmd/XAI-Research-Journal/pull/13), a follow-up PR fixing several of them.

### Decisions made

- **Decision:** Merge #10 before #11, even though #11 was opened first and is the larger PR.
  - **Why:** #10's diff was two tightly-scoped commits (model switch, `.env` loading); #11 bundles two completed experiments' results plus small code fixes. Reviewing and merging the narrower PR first keeps each PR's own diff reviewable on its own, rather than #11's large volume of result files masking whether its code changes are correct.
- **Decision:** When resolving the `max_tokens` conflict in `harness/config.yaml` that #10's merge created on #11 (main had `4096`, #11's branch had `16384`), kept #11's value.
  - **Why:** #10's `4096` had never been exercised against a real API call — #10 explicitly says "nothing paid has been run yet." #11's `16384` is what #11's own two completed, real experiments (360 real responses, all parseable) actually ran with. Evidence from a real run outweighs an untested default.
- **Decision:** Split the code-quality findings from the review into a separate tracking issue (#12) rather than blocking either PR on them, then split #12 itself into a small, low-risk cleanup PR (#13) now and a larger provider-registry refactor deferred to its own PR later.
  - **Why:** None of the findings are correctness bugs in either open PR's own diff — they're pre-existing duplication already on `main` (CSV-writing, JSONL-reading, retry wiring, matplotlib boilerplate, provider branching across `cli.py`). Bundling a refactor into either PR would have made its diff harder to review for no benefit, and the provider-registry item specifically also changes `config.py`'s schema — a bigger, separable decision that deserves its own review.

### Pivots, dead ends, disagreements

- The first review pass on #11 used a stale local `main` ref (35 commits behind `origin/main`), which made the review treat the entire pre-existing harness codebase as if #11 had introduced it, producing roughly 25 findings about files #11 doesn't even touch. Caught this by cross-checking the findings' file list against `gh pr view`'s actual file list, then re-ran the review against the correct `origin/main...origin/Adding-small-fixes` diff (7 insertions/3 deletions in 2 files) — the real diff was clean.
- A review-summary comment posted to #11 accidentally kept a line written for internal tracking ("Already fixed in #11 (...) so this resolves once #11 merges"), which reads as confusing and self-referential when posted on #11 itself. Caught after posting; a correction is still pending (see Still open).
